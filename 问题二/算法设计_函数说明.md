# 问题二核心算法函数说明

本文档对应 `problem2_core.py`，可直接用于论文“算法设计”章节。
数据读取、Excel 导出和图像绘制不在核心模块中，相关操作由

## 1. 符号与单位

| 符号 | 含义 | 单位 |
|---|---|---|
| \(\Delta t\) | 时段长度，\(\Delta t=10/60=1/6\) h | h |
| \(T\) | 每天时段数，\(T=144\) | 个 |
| \(n\) | 优化时段总数，\(n=TD\) | 个 |
| \(L_t\) | 第 \(t\) 时段负荷电量 | kWh |
| \(G_t\) | 第 \(t\) 时段光伏电量 | kWh |
| \(\pi_t\) | 第 \(t\) 时段计划电价 | 元/kWh |
| \(x_t\) | 计划购电量 | kWh |
| \(e_t\) | 紧急购电量 | kWh |
| \(c_t\) | 储能充电量 | kWh |
| \(d_t\) | 储能放电量 | kWh |
| \(E_t\) | 第 \(t\) 时段末储电量 | kWh |
| \(s_t\) | 弃光电量 | kWh |
| \(z_t\) | 充放电状态，取 0 或 1 | 无量纲 |
| \(\eta\) | 充放电效率 | 无量纲 |
| \(P_{\max}\) | 最大充放电功率 | kW |

## 2. 总体求解流程

```text
附件1、附件2
    ↓
读取电价、负荷和光伏，统一换算为10分钟电量
    ↓
建立全年能量平衡、SOC递推、功率限制和充放电互斥约束
    ↓
先求LP松弛下界
    ↓
若LP解满足充放电互斥，取 z=0/1 得到等价MILP全局最优解
    ↓
否则执行全年MILP分支定界
    ↓
逐时段、逐日、指定日期和灵敏度结果导出
```

### 3.3 `EnergyMILPModel`

`EnergyMILPModel` 保存矩阵形式的优化模型，包括：

- `objective`：目标函数系数；
- `integrality`：二进制变量标记；
- `bounds`：变量上下界；
- `constraints`：线性约束列表；
- `variable_slices`：变量块索引；
- `variable_count`：变量总数；
- `constraint_dimensions`：各类约束维数。

全年 365 天、每天 144 个时段时：

\[
n=365\times144=52560,
\]

\[
\text{变量数}=7n=367920,\qquad
\text{二进制变量数}=n=52560,
\]

\[
\text{等式约束数}=2n=105120,\qquad
\text{不等式约束数}=2n=105120.
\]

## 4. `build_energy_milp_model`

### 4.1 函数签名

```python
build_energy_milp_model(
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    price_yuan_per_kwh: np.ndarray,
    storage: StorageParameters,
    *,
    emergency_multiplier: float = 5.0,
    initial_soc_kwh: float | None = None,
    final_soc_kwh: float | None = None,
    relax_binary: bool = False,
    soc_final_policy: str = "free",
) -> EnergyMILPModel
```

### 4.2 输入

| 参数 | 类型 | 含义 | 单位 |
|---|---|---|---|
| `load_energy_kwh` | `np.ndarray` | 逐时段负荷电量 | kWh |
| `pv_energy_kwh` | `np.ndarray` | 逐时段光伏电量 | kWh |
| `price_yuan_per_kwh` | `np.ndarray` | 逐时段计划电价 | 元/kWh |
| `storage` | `StorageParameters` | 储能参数 | 混合 |
| `emergency_multiplier` | `float` | 紧急购电价倍数，默认 5 | 无量纲 |
| `initial_soc_kwh` | `float` | 初始储电量 | kWh |
| `final_soc_kwh` | `float` | 指定末端储电量 | kWh |
| `relax_binary` | `bool` | 是否进行 LP 松弛 | 无量纲 |
| `soc_final_policy` | `str` | `free`、`initial` 或 `daily-cycle` | 无量纲 |

### 4.3 输出

返回 `EnergyMILPModel`，其中已经构造完成：

\[
\min_u c^\mathsf{T}u
\]

\[
\text{s.t. }A_{\mathrm{eq}}u=b_{\mathrm{eq}},\qquad
A_{\mathrm{ineq}}u\le b_{\mathrm{ineq}},\qquad
l\le u\le h.
\]

### 4.4 目标函数

计划购电费用按计划电量 \(x_t\) 计算，紧急购电费用按
\( \lambda_e\pi_t e_t\) 计算，其中 \(\lambda_e=5\)：

\[
\min Z=\sum_{t=0}^{n-1}\left(\pi_t x_t+5\pi_t e_t\right).
\]

第一项单位为元，第二项单位为元，因此目标函数单位为元。

### 4.5 约束

**电能平衡约束**

\[
x_t+e_t+G_t+d_t=L_t+c_t+s_t.
\]

左侧为供电来源，右侧为负荷和储能充电、弃光去向。

**SOC 递推约束**

\[
E_t=E_{t-1}+\eta c_t-\frac{d_t}{\eta}.
\]

充电量以效率 \(\eta\) 进入电池，放电时电池内部消耗
\(d_t/\eta\)。

**充放电功率约束**

\[
0\le c_t\le P_{\max}\Delta t,
\qquad
0\le d_t\le P_{\max}\Delta t.
\]

代入 \(P_{\max}=5000\) kW、\(\Delta t=1/6\) h，可得每个 10 分钟时段
最大充放电电量为 \(833.333333\) kWh。

**充放电互斥约束**

\[
c_t\le Mz_t,\qquad
d_t\le M(1-z_t),\qquad
z_t\in\{0,1\},
\]

其中

\[
M=P_{\max}\Delta t=833.333333\ \text{kWh}.
\]

**SOC 安全约束**

\[
1200\le E_t\le10800\ \text{kWh}.
\]

**弃光约束**

\[
0\le s_t\le G_t.
\]

**终端 SOC 策略**

| 策略 | 末端约束 |
|---|---|
| `free` | 不固定年末 SOC |
| `initial` | 年末 SOC 回到 `initial_kwh` |
| `daily-cycle` | 每天 24:00 SOC 回到 `initial_kwh` |

### 4.6 计算复杂度

模型为稀疏线性优化模型。忽略稀疏矩阵存储开销，变量数量为
\(O(n)\)，约束数量为 \(O(n)\)。全年模型的主要计算压力来自
\(n=52560\) 个二进制变量；若 LP 松弛解已满足互斥约束，则不需要
执行全年分支定界。

## 5. `solve_energy_dispatch`

### 5.1 函数签名

```python
solve_energy_dispatch(
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    price_yuan_per_kwh: np.ndarray,
    storage: StorageParameters,
    *,
    emergency_multiplier: float = 5.0,
    initial_soc_kwh: float | None = None,
    final_soc_kwh: float | None = None,
    relax_binary: bool = False,
    soc_final_policy: str = "free",
    time_limit_s: float = 300.0,
    logger: Callable[[str], None] | None = None,
) -> DispatchSolution
```

### 5.2 输入

输入与 `build_energy_milp_model` 基本一致，额外增加：

| 参数 | 含义 |
|---|---|
| `time_limit_s` | 求解器时间上限，单位 s |
| `logger` | 可选的逐步打印函数 |

### 5.3 输出

返回 `DispatchSolution`。其中：

\[
Z_{\text{normal}}=\sum_t\pi_tx_t,
\]

\[
Z_{\text{emergency}}=5\sum_t\pi_te_t,
\]

\[
Z_{\text{total}}=Z_{\text{normal}}+Z_{\text{emergency}}.
\]

所有电量以 kWh 返回，所有费用以元返回。

### 5.4 求解逻辑

1. 调用 `build_energy_milp_model` 构造矩阵；
2. 调用 SciPy HiGHS 求解器；
3. 检查求解器是否返回成功状态；
4. 提取 \(x,e,c,d,s\)；
5. 用 \(c,d\) 重新递推 SOC，减少线性方程组的数值残差；
6. 计算计划购电费用、紧急购电费用和总费用；
7. 计算最大同时充放电量。

### 5.5 LP 与 MILP

- `relax_binary=True` 时求解 LP 松弛，提供费用下界；
- `relax_binary=False` 时求解 MILP，得到实际可执行策略；
- 若 LP 解满足

\[
\max_t\min(c_t,d_t)\le10^{-7}\ \text{kWh},
\]

则可令 \(z_t=1\) 当 \(c_t>0\)，否则令 \(z_t=0\)，该 LP 解同时是
MILP 的可行解，且其目标值已达到 LP 下界，因此也是 MILP 全局最优解。

## 6. `validate_dispatch`

### 6.1 函数签名

```python
validate_dispatch(
    solution: DispatchSolution,
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    storage: StorageParameters,
    *,
    tolerance: float = 1e-5,
) -> dict[str, float]
```

### 6.2 输出指标

| 指标 | 含义 | 单位 |
|---|---|---|
| 最大电能平衡残差 | 能量平衡方程误差 | kWh |
| 最大 SOC 递推残差 | SOC 递推方程误差 | kWh |
| 最大紧急购电触发残差 | 紧急购电缺口误差 | kWh |
| SOC 最小值 | 最小储电量 | kWh |
| SOC 最大值 | 最大储电量 | kWh |
| 最大充电功率 | 充电功率峰值 | kW |
| 最大放电功率 | 放电功率峰值 | kW |
| 最大同时充放电量 | 互斥性检验指标 | kWh |

检验公式为：

\[
r_t=x_t+e_t+G_t+d_t-L_t-c_t-s_t.
\]

\[
r_t^{SOC}=E_t-\left(E_{t-1}+\eta c_t-\frac{d_t}{\eta}\right).
\]

当任一残差超过容差时，函数抛出 `ValueError`。

## 7. `baseline_dispatch`

### 7.1 函数签名

```python
baseline_dispatch(
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    price_yuan_per_kwh: np.ndarray,
    storage: StorageParameters,
) -> DispatchSolution
```

### 7.2 基准策略

储能不动作，即 \(c_t=d_t=0\)，缺口全部采用计划购电：

\[
x_t=\max(L_t-G_t,0),
\]

\[
s_t=\max(G_t-L_t,0).
\]

输出为储能不动作时的计划购电量、弃光量和购电费用，单位分别为
kWh、kWh 和元。

## 9. `run_sensitivity_analysis`

### 9.1 函数签名

```python
run_sensitivity_analysis(
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    price_144_yuan_per_kwh: np.ndarray,
    storage: StorageParameters,
    *,
    soc_final_policy: str = "free",
    logger=None,
) -> pd.DataFrame
```

### 9.2 扰动设置

| 因素 | 扰动水平 |
|---|---|
| 负荷 | \(-10\%,-5\%,0,5\%,10\%\) |
| 光伏 | \(-10\%,-5\%,0,5\%,10\%\) |
| 电价水平 | \(-10\%,-5\%,0,5\%,10\%\) |
| 峰谷价差 | 0.8、1.0、1.2 倍 |
| 充放电效率 | \(-10\%,-5\%,0,5\%,10\%\) |
| 紧急电价倍数 | 1、3、5、7、10 |

### 9.3 输出

每个情景均重新求解全年模型，输出：

- 全年总购电费；
- 输出期计划购电量和紧急购电量；
- 输出期计划购电费和紧急购电费；
- 指定日期合计购电费；
- 年末储电量；
- 最大同时充放电量；
- 相对基准费用变化率。

相对变化率定义为：

\[
\Delta Z(\theta)=
\frac{Z(\theta)-Z_0}{Z_0}\times100\%.
\]

## 10. 标准化、训练集和测试集说明

本问题是确定性线性优化问题，不是统计学习模型，因此：

1. 不对负荷、光伏和电价做 z-score 或 min-max 标准化；标准化会改变
   电量和费用的物理线性关系。
2. 不划分训练集和测试集；优化问题中的参数来自附件，决策变量通过
   线性约束和全局求解器确定。
3. 灵敏度分析不是“测试集预测”，而是对输入参数进行重新优化，用
   来考察最优目标值和调度策略的变化。

## 12. `result2.xlsx` 输出规范

输出文件必须严格保持官方模板的 3 个工作表：

```text
计划购电量
充放电量
紧急购电量
```

各工作表格式如下：

**计划购电量**

- 第 1 列为日期；
- 第 2 至第 145 列为 144 个 10 分钟时段的计划购电量；
- 第 146 列为全天计划购电量；
- 第 147 列为全天计划购电费；
- 日期格式保持官方模板的 `mm-dd-yy`；
- 2025-02-01 至 2025-12-31 共 334 行数据。

**充放电量**

- 列头保持为：`日期`、`时间段`、`充电量`、`放电量`、`时刻`、`储电量`；
- 每天 6 行，对应 0:00-4:00、4:00-8:00、8:00-12:00、
  12:00-16:00、16:00-20:00、20:00-24:00；
- 每天第一行写日期；
- 每天第一行 `时刻=0:00`，第二行 `时刻=24:00`；
- 单位统一为 kWh，不在官方列头中额外添写 kW。

**紧急购电量**

- 列头保持为：`日期`、`购电时间段`、`购电量`；
- 仅写实际发生紧急购电的连续时间段；
- 同一日期有多个连续事件时，只在第一个事件行写日期；
- 不把没有发生紧急购电的日期逐行填满。
