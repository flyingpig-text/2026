# 问题4核心算法函数说明

## 1. 算法目标与统一符号

问题4在附件4实时波动电价下重新计算问题2和问题3。储能设备满足

$$
E_{\min}=1200\ \text{kWh},\qquad
E_{\max}=10800\ \text{kWh},
$$

$$
P_{\max}=5000\ \text{kW},\qquad
\eta_c=\eta_d=0.9,
$$

每个时段长度为

$$
\Delta t=\frac{10}{60}=\frac{1}{6}\ \text{h},
$$

每天包含 \(T=144\) 个10分钟时段。储能跨日连续，并且每天满足

$$
E_{d,0}=E_{d,144}=6000\ \text{kWh}.
$$

问题4-3制定计划和调整策略时，不使用未来实际电价。第 \(d\) 天第
\(t\) 个时段的决策价格预测为

$$
\hat\pi_{d,t}
=
\frac{1}{d-1}
\sum_{r=1}^{d-1}\pi_{r,t}^{RT},
$$

其中 \(\pi_{r,t}^{RT}\) 为附件4中已经实现的实时电价。实际结算仍使用
当日附件4实际价格 \(\pi_{d,t}^{RT}\)。

## 2. 核心函数调用关系

```text
build_causal_price_forecast
        |
        v
solve_problem43_year
        |
        v
solve_problem43_day
        |
        +--> solve_initial_plan
        |
        +--> solve_adjustment_stage

solve_problem42_year

```

核心算法集中在 `problem4_core.py`，文件读取、结果写出和绘图由
`problem4_run.py` 负责。

## 3. `build_causal_price_forecast`

### 3.1 函数签名

```python
build_causal_price_forecast(
    price_by_date: Mapping[date, np.ndarray],
    periods_per_day: int = 144,
) -> dict[date, np.ndarray]
```

### 3.2 函数功能

构造严格因果的实时电价预测。第 \(d\) 天只使用第1天至第 \(d-1\) 天
已经实现的附件4数据，不使用决策日当天未来时段，也不使用未来日期。

### 3.3 输入说明

| 输入 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `price_by_date` | `Mapping[date, np.ndarray]` | 元/kWh | 日期到144维实际实时电价的映射 |
| `periods_per_day` | `int` | 无量纲 | 每天时段数，默认144 |

### 3.4 输出说明

| 输出 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `forecast_by_date` | `dict[date, np.ndarray]` | 元/kWh | 日期到144维因果价格预测的映射 |

### 3.5 计算过程

1. 按日期升序排列实时电价序列；
2. 维护每个10分钟时段的历史累计价格；
3. 第 \(d\) 天使用此前所有日期的同时段均值作为预测；
4. 把当天实际价格加入累计量，供下一天使用。

时间复杂度和空间复杂度分别为

$$
O(DT),\qquad O(DT).
$$

## 4. `solve_problem42_day`

### 4.1 函数签名

```python
solve_problem42_day(
    load_energy_kwh: np.ndarray,
    pv_energy_kwh: np.ndarray,
    price_yuan_per_kwh: np.ndarray,
    storage: StorageLike,
    initial_soc_kwh: float | None = None,
    final_soc_kwh: float | None = None,
) -> InitialPlanResult
```

### 4.2 函数功能

求解某一日期下问题4-2的单日确定性 MILP。目标是在实时电价下确定计划
购电量、紧急购电量和储能充放电计划。

### 4.3 输入说明

| 输入 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `load_energy_kwh` | `np.ndarray` | kWh | 144维小区负荷电量 |
| `pv_energy_kwh` | `np.ndarray` | kWh | 144维光伏实际发电量 |
| `price_yuan_per_kwh` | `np.ndarray` | 元/kWh | 144维实时电价 |
| `storage` | `StorageLike` | - | 储能容量、功率、SOC上下限和效率 |
| `initial_soc_kwh` | `float` 或 `None` | kWh | 0:00储电量，默认6000 kWh |
| `final_soc_kwh` | `float` 或 `None` | kWh | 24:00储电量，默认与初始值相同 |

### 4.4 输出说明

函数返回 `InitialPlanResult`。

| 输出字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `planned_purchase_kwh` | `np.ndarray` | kWh | 逐时段计划购电量 |
| `emergency_purchase_kwh` | `np.ndarray` | kWh | 逐时段紧急购电量 |
| `charge_kwh` | `np.ndarray` | kWh | 逐时段充电量 |
| `discharge_kwh` | `np.ndarray` | kWh | 逐时段放电量 |
| `curtail_kwh` | `np.ndarray` | kWh | 逐时段弃光电量 |
| `soc_kwh` | `np.ndarray` | kWh | 长度145的储电量轨迹 |
| `planned_cost_yuan` | `float` | 元 | 计划购电费 |
| `emergency_cost_yuan` | `float` | 元 | 紧急购电费 |
| `total_cost_yuan` | `float` | 元 | 总购电费 |

### 4.5 模型约束

目标函数为

$$
\min Z_2
=
\sum_{t=1}^{T}
\left[
\pi_t x_t+5\pi_t e_t
\right].
$$

电能平衡：

$$
x_t+e_t+G_t\Delta t+D_t
=
L_t\Delta t+C_t+S_t.
$$

储能递推：

$$
E_t=E_{t-1}+\eta C_t-\frac{D_t}{\eta}.
$$

功率和容量约束：

$$
0\leq C_t,D_t\leq5000\Delta t,
$$

$$
C_t\leq5000\Delta t\,z_t,
\qquad
D_t\leq5000\Delta t(1-z_t),
$$

$$
1200\leq E_t\leq10800.
$$

单日 MILP 含 \(7\times144=1008\) 个变量，其中144个二值变量。

## 5. `solve_problem43_day`

### 5.1 函数签名

```python
solve_problem43_day(
    load_energy_kwh: np.ndarray,
    actual_pv_energy_kwh: np.ndarray,
    actual_price_yuan_per_kwh: np.ndarray,
    decision_price_yuan_per_kwh: np.ndarray,
    forecast_by_hour: Mapping[int, np.ndarray],
    storage: StorageLike,
    forecast_scale: float = 1.0,
    settlement_mode: str = "plan_full",
) -> RollingDayResult
```

### 5.2 函数功能

完成某一日期的问题4-3滚动优化，包括0:00初始计划以及
6:00、12:00、18:00三个阶段调整。未来实际电价只用于最终费用结算，
不参与计划和调整求解。

### 5.3 输入说明

| 输入 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `load_energy_kwh` | `np.ndarray` | kWh | 144维实际负荷电量 |
| `actual_pv_energy_kwh` | `np.ndarray` | kWh | 144维实际光伏电量 |
| `actual_price_yuan_per_kwh` | `np.ndarray` | 元/kWh | 当日实际实时电价，只用于结算 |
| `decision_price_yuan_per_kwh` | `np.ndarray` | 元/kWh | 因果价格预测，用于计划和调整 |
| `forecast_by_hour` | `Mapping[int,np.ndarray]` | kW | 0、6、12、18时发布的24小时光伏预报 |
| `storage` | `StorageLike` | - | 储能参数 |
| `forecast_scale` | `float` | 无量纲 | 光伏预报整体缩放系数 |
| `settlement_mode` | `str` | - | `plan_full`或`actual_base` |

### 5.4 输出说明

函数返回 `RollingDayResult`。

| 输出字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `plan_purchase_kwh` | `np.ndarray` | kWh | 0:00形成的计划购电量 |
| `adjusted_purchase_kwh` | `np.ndarray` | kWh | 最终调整购电量 |
| `charge_kwh` | `np.ndarray` | kWh | 最终充电量 |
| `discharge_kwh` | `np.ndarray` | kWh | 最终放电量 |
| `soc_kwh` | `np.ndarray` | kWh | 最终储电量轨迹 |
| `emergency_purchase_kwh` | `np.ndarray` | kWh | 实际紧急购电量 |
| `actual_curtail_kwh` | `np.ndarray` | kWh | 实际弃光量 |
| `up_kwh`、`down_kwh` | `np.ndarray` | kWh | 上调和下调电量 |
| `plan_cost_kwh_yuan` | `np.ndarray` | 元 | 计划购电费 |
| `adjustment_cost_yuan` | `np.ndarray` | 元 | 调整费用 |
| `emergency_cost_yuan` | `np.ndarray` | 元 | 紧急购电费 |
| `total_cost_yuan` | `float` | 元 | 单日总费用 |

### 5.5 索引边界

| 决策时刻 | 时段索引 | 可调整时段 |
|---|---:|---|
| 0:00 | 0 | 1至144 |
| 6:00 | 36 | 37至144 |
| 12:00 | 72 | 73至144 |
| 18:00 | 108 | 109至144 |

已经执行的时段不能被后续阶段修改。

## 6. `solve_adjustment`

### 6.1 函数签名

```python
solve_adjustment(
    load_energy_kwh: np.ndarray,
    forecast_pv_energy_kwh: np.ndarray,
    decision_price_yuan_per_kwh: np.ndarray,
    plan_purchase_kwh: np.ndarray,
    storage: StorageLike,
    initial_soc_kwh: float,
    final_soc_kwh: float | None = None,
    settlement_mode: str = "plan_full",
) -> AdjustmentResult
```

### 6.2 函数功能

求解一个滚动阶段的调整购电 MILP。该函数处理尚未执行的时段，并以
0:00计划购电量作为调整基准。

### 6.3 输入说明

| 输入 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `load_energy_kwh` | `np.ndarray` | kWh | 待调整时段负荷 |
| `forecast_pv_energy_kwh` | `np.ndarray` | kWh | 当前预报光伏电量 |
| `decision_price_yuan_per_kwh` | `np.ndarray` | 元/kWh | 当前可得价格预测 |
| `plan_purchase_kwh` | `np.ndarray` | kWh | 原始计划购电量 |
| `storage` | `StorageLike` | - | 储能参数 |
| `initial_soc_kwh` | `float` | kWh | 阶段初储电量 |
| `final_soc_kwh` | `float`或`None` | kWh | 阶段末储电量，默认6000 kWh |
| `settlement_mode` | `str` | - | 费用口径 |

### 6.4 输出说明

函数返回 `AdjustmentResult`。

| 输出字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `adjusted_purchase_kwh` | `np.ndarray` | kWh | 调整后的购电量 |
| `base_purchase_kwh` | `np.ndarray` | kWh | 基础结算电量 |
| `up_kwh` | `np.ndarray` | kWh | 相对原计划的上调量 |
| `down_kwh` | `np.ndarray` | kWh | 相对原计划的下调量 |
| `charge_kwh`、`discharge_kwh` | `np.ndarray` | kWh | 充放电量 |
| `curtail_kwh` | `np.ndarray` | kWh | 弃光量 |
| `soc_kwh` | `np.ndarray` | kWh | 储电量轨迹 |

### 6.5 偏差与费用系数

$$
\Delta_t^{+}-\Delta_t^{-}
=
X_t^{F}-X_t^{P}.
$$

阶段目标中的调整费用为

$$
0.5\hat\pi_t\Delta_t^{-}
+
1.5\hat\pi_t\Delta_t^{+}.
$$

其中 \(\hat\pi_t\) 为决策时可获得的因果价格预测。最终实际费用使用
\(\pi_t^{RT}\)结算。下调电量的费用系数为0.5，上调电量的费用系数为1.5。

## 9. 计算复杂度

问题4-2单日模型含144个0-1变量，全年按日求解：

$$
334\ \text{次 MILP}.
$$

问题4-3每天包含1次初始计划和3次阶段调整，共

$$
334\times4=1336\ \text{次 MILP}.
$$

阶段时段数分别为144、108、72和36，模型规模随剩余时段数线性下降。

## 10. 算法正确性检查

1. 每日检查 \(E_{d,0}=E_{d,144}=6000\ \text{kWh}\)；
2. 检查 \(1200\leq E_{d,t}\leq10800\ \text{kWh}\)；
3. 检查充电量和放电量均不超过 \(5000\Delta t\)；
4. 检查 \(C_tD_t\approx0\)；
5. 检查电能平衡残差；
6. 检查问题4-3计划和调整只使用历史价格预测；
7. 检查最终费用使用附件4当日实际实时电价结算。
