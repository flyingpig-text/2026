# 问题4核心算法函数说明

## 1. 模块职责

`problem4_core.py` 负责：

1. 构造问题四的联合负荷、光伏和电价情景；
2. 求解问题4-2的随机计划和实时储能执行；
3. 求解问题4-3的0:00计划、三次调整购电和实时执行；
4. 按跨日连续SOC完成全年调度。

`problem4_run.py` 负责附件读取、约束校验、官方模板输出、CSV、JSON和
图形生成。所有数据均从 `题目/附件` 或 `题目/附件/附件5` 读取。

## 2. 主要函数调用关系

```text
build_causal_price_forecast
        |
        v
build_problem4_scenario_windows
        |
        +--> solve_problem42_day --> solve_flexible_purchase_stage
        |                       --> execute_block_with_future_value
        |
        +--> solve_problem43_year --> run_rolling_day
                                  --> solve_flexible_purchase_stage
                                  --> execute_block_with_future_value
```

## 3. `build_causal_price_forecast`

### 3.1 签名

```python
build_causal_price_forecast(
    price_by_date: Mapping[date, np.ndarray],
    periods_per_day: int = 144,
) -> dict[date, np.ndarray]
```

### 3.2 功能

为每个日期构造只使用此前历史价格的价格基线。第 \(d\) 天的预测为

\[
\widehat\pi_{d,t}
=
\frac{1}{d-1}
\sum_{r<d}\pi_{r,t}.
\]

该函数仅作为0:00情景的基础预测。问题四实际使用
`build_problem4_scenario_windows`按历史日期配对电价情景。

## 4. `build_problem4_scenario_windows`

### 4.1 签名

```python
build_problem4_scenario_windows(
    data,
    forecast_by_date,
    current_date,
    price_by_date,
    expected_price_yuan_per_kwh,
    fallback_load_profile_kwh,
    *,
    scenario_count=5,
    lookback_days=30,
    forecast_scale=1.0,
) -> dict[int, dict]
```

### 4.2 输出窗口

返回键为0、6、12、18的四个窗口。每个窗口包含：

| 字段 | 含义 |
|---|---|
| `load_kwh` | 形状 `(情景数, 剩余时段数)` 的负荷电量 |
| `pv_kwh` | 形状 `(情景数, 剩余时段数)` 的光伏电量 |
| `price_yuan_per_kwh` | 各时段期望电价 |
| `price_scenarios_yuan_per_kwh` | 各情景实际采用的电价曲线 |
| `probabilities` | 情景概率 |
| `current_intervals` | 当前日尚未执行的时段数 |
| `selected_error_dates` | 配对选取的历史日期 |

### 4.3 价格情景

0:00使用历史同日实际价格。6:00、12:00、18:00使用

\[
\pi_{d,t}^{\omega}
=
\pi_{d,s}^{\text{actual}}
+\pi_{\tau,t}
-\pi_{\tau,s},
\qquad t>s.
\]

这里只读取已经观察到的当日价格 \(\pi_{d,s}^{\text{actual}}\)，不读取
当天未来实际价格。

## 5. `solve_problem42_day`

### 5.1 签名

```python
solve_problem42_day(
    load_energy_kwh,
    pv_energy_kwh,
    actual_price_yuan_per_kwh,
    scenario_window,
    storage,
    initial_soc_kwh=None,
    terminal_value_yuan_per_kwh=0.0,
) -> InitialPlanResult
```

### 5.2 求解步骤

1. 用0:00联合情景求解共享计划购电量 \(g_t\)；
2. 固定 \(g_t\)，按实际负荷、实际光伏和逐时段实际电价执行储能；
3. 用附件4实际价格计算计划购电费、紧急购电费和总费用；
4. 返回计划、充放电、SOC、弃光和紧急购电结果。

计划阶段的储能动作按情景追索，实际输出只使用真实执行轨迹。

## 6. `solve_problem43_year`

### 6.1 签名

```python
solve_problem43_year(
    data,
    forecast_by_date,
    storage,
    price_by_date,
    decision_price_by_date=None,
    fallback_load_profile_kwh=None,
    *,
    scenario_count=5,
    lookback_days=30,
    collect_update_scenarios=False,
) -> tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]
```

### 6.2 年度流程

1. 从2025-01-01的6000 kWh开始；
2. 每天构造0、6、12、18四个联合情景窗口；
3. 0:00求解共享计划 \(g_t\)；
4. 6:00、12:00、18:00分别更新未执行时段的最终购电量 \(q_t\)；
5. 每个6小时块内按实际负荷、光伏和已观察价格逐10分钟执行储能；
6. 把当天末SOC传给下一天；
7. 只返回2025-02-01至2025-12-31的结果。

如果 `collect_update_scenarios=True`，还会额外比较仅0:00、更新至
6:00、更新至12:00和更新至18:00四种情形；正式全年输出默认关闭该
额外分析以减少重复求解。

## 7. 共用底层函数

问题四复用问题三算法中的以下函数：

| 函数 | 作用 |
|---|---|
| `solve_flexible_purchase_stage` | 共享购电量、情景追索的随机LP |
| `execute_block_with_future_value` | 用当前实际价格和未来价值执行储能 |
| `settle_actual_dispatch` | 按实际电价结算计划和紧急购电 |
| `run_rolling_day` | 组织0、6、12、18四个执行块 |

`solve_flexible_purchase_stage`支持可选的
`scenario_price_yuan_per_kwh`。给定后，紧急购电按情景价格计价，计划
购电按情景期望价格计价。

## 8. 主要边界条件

\[
0\le c_t,d_t\le5000\Delta t,
\]

\[
1200\le E_t\le10800,
\]

\[
E_t=E_{t-1}+\eta c_t-\frac{d_t}{\eta},
\]

\[
E_{d,0}=E_{d-1,144}.
\]

## 9. 输出与校验

核心输出为：

```text
output/result4-2.xlsx
output/result4-3.xlsx
```

工作簿使用官方模板，保留工作表顺序、表头、日期行和147列宽表。
程序在写出前校验日期数、144个10分钟时段、SOC递推、跨日连续性、
功率上限、充放电互斥和能量平衡。
